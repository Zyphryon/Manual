# Runtime

This chapter covers what runs a Zyphryon program around the scene: the application host (`ZyRuntime::Kernel`) and
how an application boots it, the startup parameters and the settings file, the command line, the services and how
code finds them, engine modules and plugins, the job system, input, the window, the audio service in brief, the
behaviour-tree runtime (`Zyphryon.AI`), profiling, and platform notes. It leans on `getting-started.md` (the CMake
setup and a first program), `scene.md` (the scene service ticks inside this loop), `content.md` (mounts, files and
resources), `graphics.md` (drivers and drawing), `audio.md` (the audio service in full), `ai.md` (behaviour trees in full), `network.md` (the network
and replication services) and `base.md` (delegates, JSON, threads).

## 1. How a program is put together

### 1.1 The kernel and the entry point

A Zyphryon program is one class derived from `ZyRuntime::Kernel`, named in `ZY_APPLICATION`:

```cpp
#include <Zyphryon.Runtime/Entry.hpp>

ZY_APPLICATION(Demo::Application)
```

`ZY_APPLICATION(Type)` writes `main`, which calls `ZyRuntime::Launch<Type>`. That constructs the kernel and calls
`Kernel::Run(Count, Arguments, ZyRegisterModules())`. `ZyRegisterModules()` is generated by the CMake function
`ZyApplyModules(<target>)`: it lists every engine module registered with `ZyRegisterModule` (the D3D11 and OpenGL
graphic drivers, and any module of your own). Call `ZyApplyModules` on your executable (see `getting-started.md`).

`Kernel` is itself the service registry (`ZyEngine::Subsystem::Host`), so a kernel calls `GetService<T>()` and
`Register<T>()` directly.

| Member | Use |
|---|---|
| `virtual void OnConfigure(Ref<Startup> Startup)` | Before any service exists. Change the startup parameters. |
| `virtual Bool OnInitialize()` | After every service is up and the modules attached. Return `false` to exit at once. |
| `virtual void OnTick(Real64 Delta)` | Once per frame, before the services tick. `Delta` in seconds. |
| `virtual void OnTerminate()` | Once, before modules detach and services are torn down. |
| `void Quit()` | Ends the loop after the current frame. |
| `ConstRef<Environment> GetEnvironment() const` | The parsed command line. |
| `ConstRef<Meter> GetMeter() const` | The frame meter: `GetMeter().GetRate()` is frames per second over the last half second. |
| `void Save(JsonObject Root)` | Writes the user-changeable startup parameters as they now stand. |

### 1.2 What `Kernel::Run` does

1. `Environment::Parse` reads the command line.
2. `OnConfigure(Ref<Startup>)` lets the application change the startup parameters before any service exists.
3. `Initialize` registers the services, attaches the modules, initializes graphics and audio, then calls
   `OnInitialize()`. The window is shown only if `OnInitialize` returned `true`.
4. The frame loop: `Tick()` until `Quit()` is called or the window closes. On the web the browser owns the loop
   (`emscripten_set_main_loop_arg`), and `Run` never returns to its caller's frame.
5. `OnTerminate()`, then modules detach, every service is torn down, and the log is flushed.

If a service the application needs fails during step 3 (the window cannot open, no graphic driver starts), the
kernel never calls `OnInitialize`, never ticks, and never calls `OnTerminate`. It detaches whatever modules it
attached and tears down.

### 1.3 The services the kernel registers

| Order | Service | Notes |
|---|---|---|
| 1 | `ZyPlatform::Service` | Window and display. Not headless. Failing to open the window ends the start. |
| 2 | `ZyInput::Service` | Keyboard, mouse, touch, actions. Not headless. |
| 3 | `ZyJob::Service` | Worker lanes. |
| 4 | `ZyNetwork::Service` | Unregistered again, with the warning `Kernel: Failed to initialize network service`, if it fails to start. |
| 5 | `ZyContent::Service` | Mounts, files, resources (see `content.md`). |
| 6 | `ZyScene::Service` | The world (see `scene.md`). |
| 7 | `ZyReplication::Service` | Scene replication (see `network.md`). |
| 8 | `ZyGraphic::Service` | GPU driver. Not headless. |
| 9 | `ZyAudio::Service` | Sound output. Not headless. A failed device is a warning and the program runs silent. |
| 10 | `ZyRender::Service` | Renderer over graphics. Not headless. |

Then each module's `OnAttach(Host)` runs (graphic drivers register themselves here), then the graphic service picks
a driver and opens the swapchain on the window, then the audio device opens.

When no colour format was asked for, the kernel picks one from the window's monitor: `RGBA16Float` on an HDR
monitor, `RGBA8UIntNorm_sRGB` otherwise. The depth format defaults to none.

### 1.4 One frame

```cpp
Bool Kernel::Tick()
{
    const Real64 Delta = mTimer.Step();
    mMeter.Record(Delta);

    OnTick(Delta);                               // the application's own work
    ZyEngine::Subsystem::Host::Tick(Delta);      // every service's OnTick

    // With Startup::SetRate(N), wait out what is left of 1/N of a second (not on the web).
    ...
    ZY_PROFILE_FRAME;
    return mAlive;
}
```

What runs inside the services' tick:

| Service | Its `OnTick` |
|---|---|
| `ZyPlatform::Service` | Polls the window, takes the frame's events, hands them to the input service. |
| `ZyJob::Service` | Runs the jobs queued on `ZyJob::Lane::Main`. |
| `ZyContent::Service` | Finishes loads: `OnCreate` on the main thread, completion callbacks. |
| `ZyScene::Service` | Ticks the clock, then runs every phase (`World::Progress`). |
| `ZyGraphic::Service` | Flushes the frame's commands to the GPU thread. |

The order between services follows the registry's storage and is not something to rely on. Work that must run at a
precise point of the frame belongs in a scene system in the right phase. Two consequences of the kernel calling
`OnTick` first:

- `OnTick` sees what the scene's systems wrote on the previous frame.
- `OnTick` sees the input polled on the previous frame; systems see this frame's.

Code in a system runs on the main thread, once per frame, in phase order, unless the system is spread (see
`scene.md`).

The first frame's delta leaves out start-up time: the kernel resets its timer just before the loop.

### 1.5 `Startup`: the parameters before any service

```cpp
class ZyRuntime::Startup final
{
public:
    struct Window  { Str Monitor; Str Title = "Undefined"; UInt32 Width = 1024; UInt32 Height = 768;
                     Bool Fullscreen = false; Bool Borderless = false; };
    struct Audio   { Str Adapter; Bool Pause = false; };
    struct Graphic { Str16 Driver; Bool Tearless = true;
                     ZyGraphic::TextureFormat ColorFormat = ZyGraphic::TextureFormat::Unspecified;
                     ZyGraphic::TextureFormat DepthFormat = ZyGraphic::TextureFormat::Unspecified; };

    void SetHeadless(Bool Headless);    Bool IsHeadless() const;
    void SetRate(UInt32 Rate);          UInt32 GetRate() const;    // 0 = as fast as frames come
    void SetWindow(ConstRef<Window>);   ConstRef<Window>  GetWindow() const;
    void SetAudio(ConstRef<Audio>);     ConstRef<Audio>   GetAudio() const;
    void SetGraphic(ConstRef<Graphic>); ConstRef<Graphic> GetGraphic() const;

    void Load(JsonObject Root);         // reads the user-changeable parameters
    void Save(JsonObject Root) const;
};
```

| Field | Meaning |
|---|---|
| `Window::Monitor` | The monitor to open on, by name; empty for the primary one. |
| `Window::Width`, `Height` | Pixels **before** the monitor's scale is applied. |
| `Window::Fullscreen`, `Borderless` | Cover the monitor; open without a frame. |
| `Graphic::Driver` | `"D3D11"` or `"OpenGL"`. Empty picks the one registered at the highest priority (D3D11 registers `High`, OpenGL `Low`). |
| `Graphic::Tearless` | Wait for the vertical blank when presenting. |
| `Graphic::ColorFormat`, `DepthFormat` | The swapchain formats; `Unspecified` picks from the monitor (colour) or none (depth). |
| `Audio::Adapter` | The output device by name; empty for the default. |
| `Audio::Pause` | Pause sound while the window is out of focus. |

`Startup::Load`/`Save` use this JSON shape (lower-case keys under capitalized sections). The title, the borderless
flag, the formats, the rate and the headless flag are not part of it; they are the application's to set.

```json
{
  "Window":  { "monitor": "", "width": 1280, "height": 720, "fullscreen": false },
  "Graphic": { "driver": "D3D11", "tearless": true },
  "Audio":   { "adapter": "", "pause": true }
}
```

`Kernel::Save(Root)` first copies the live state into the startup parameters (the window's monitor, its size
divided by its scale unless it is fullscreen, the fullscreen flag, and the graphic service's tearless flag), then
writes them.

#### A settings file that survives restarts

`OnConfigure` runs before the content service exists, so it reads the file through `Filesystem` directly
(`base.md`, section 12). `OnTerminate` runs while the services are still alive, so `Save` can read the window.

```cpp
class Application final : public ZyRuntime::Kernel
{
protected:

    void OnConfigure(Ref<ZyRuntime::Startup> Startup) override
    {
        mSettings = Filesystem::Path::Join(Filesystem::GetDataFolder("Acme", "Hello"), '/', "Settings.json");

        ZyRuntime::Startup::Window Window = Startup.GetWindow();
        Window.Title = "Hello";
        Startup.SetWindow(Window);

        if (Blob Data; Filesystem::Read(mSettings, Data) == Filesystem::Result::Success)
        {
            JsonValue Root = JsonDocument::Parse(Text(Data.GetData<Char>(), Data.GetSize()));

            if (Root.IsObject())
            {
                Startup.Load(JsonObject(Root));
            }
        }
    }

    void OnTerminate() override
    {
        JsonValue Root;
        Root.SetObject();
        Save(JsonObject(Root));

        Filesystem::Ensure(mSettings);                          // makes the folder the file goes in
        Filesystem::Write(mSettings, JsonDocument::Dump(Root));
    }

private:

    Filesystem::Path mSettings;
};
```

`GetDataFolder` returns an empty path where the system has none (the web); check it before relying on it.

### 1.6 The command line: `Environment`

`Kernel::GetEnvironment()` returns the parsed command line. Switches start with `--`. `--name=value`,
`--name value` and `--no-name` (reads `false`) are understood; anything else is an operand.

| Method | Reads |
|---|---|
| `Bool Contains(Text Name) const` | Whether the switch was given. |
| `Text GetText(Text Name, Text Default) const` | Its text. |
| `Bool GetBool(Text Name, Bool Default) const` | Its flag. |
| `Type GetNumber<Type>(Text Name, Type Default) const` | Its number. |
| `Type GetEnum<Type>(Text Name, Type Default) const` | An enum by name. |
| `ConstSpan<Text> GetOperands() const` | Everything that was not a switch, in order. |

```cpp
void OnConfigure(Ref<ZyRuntime::Startup> Startup) override
{
    ConstRef<Environment> Command = GetEnvironment();

    if (Command.GetBool("server", false))
    {
        Startup.SetHeadless(true);
        Startup.SetRate(Command.GetNumber<UInt32>("rate", 30));
    }

    if (const ConstSpan<Text> Files = GetEnvironment().GetOperands(); !Files.IsEmpty())
    {
        mLevel = Files[0];                                     // a Str member: the operand's Text dies with Command
    }
}
```

```
Game level.dat --server --rate=20
Game --no-server
```

### 1.7 Headless

Headless comes two ways:

| Way | How | What is left out |
|---|---|---|
| Build time | `ZY_MODE_HEADLESS=ON` (the `headless` preset) | The window, input, graphic, audio and render modules are not compiled, and the graphic drivers are not built. |
| Run time | `Startup.SetHeadless(true)` in `OnConfigure` | The same five services are not registered, in a normal build. |

Either way the job, network, content, scene and replication services run. A headless loop has no vertical blank to
wait for, so give it a rate with `Startup.SetRate(N)` or it spins a core. Code shared with a windowed build checks
`GetService<T>()` for an empty retainer, and code naming the left-out types sits behind
`#if !defined(ZY_MODE_HEADLESS)`.

A headless content service has no graphic, render or audio loaders, so `.tex`, `.msh`, `.mdl`, `.fnt`, `.snd` and
the other formats those services register do not load there (see `content.md`).

## 2. Services and how code finds them

### 2.1 The pieces

| Type | Role |
|---|---|
| `ZyEngine::Subsystem` | Base of every service. Virtual `OnTick(Real64 Delta)` and `OnTeardown()`. `GetHost()` returns its host. |
| `ZyEngine::Subsystem::Host` | `ZyEngine::System<Subsystem>`, the registry the kernel is. |
| `System::Register<T>(Args...)` | Creates and registers a service, constructed with the host and `Args`. Asserts if one of that type exists. Returns `Retainer<T>`. |
| `System::GetService<T>()` | `Retainer<T>`, empty when none is registered. |
| `System::Unregister<T>()` | Drops it without calling `OnTeardown`. |
| `ZyEngine::Locator<A, B, ...>` | A base class that resolves services once, at construction, and asserts they exist. `GetService<T>()` returns `Ref<T>`. |
| `ZyEngine::Module` | An engine module (`GetName`, `GetVersion`, `OnAttach(Host)`, `OnDetach(Host)`). |

### 2.2 Finding a service

From a kernel (it is the host), use the nullable form:

```cpp
if (ConstRetainer<ZyAudio::Service> Audio = GetService<ZyAudio::Service>())
{
    Audio->SetMasterVolume(0.8f);
}

// When the service is certain to exist, take a reference. The host keeps it alive.
Ref<ZyScene::Service> Scene = * GetService<ZyScene::Service>();
```

A class of your own that needs several services inherits `Locator` and is constructed with the host:

```cpp
class Spawner final : public ZyEngine::Locator<ZyJob::Service, ZyScene::Service, ZyContent::Service>
{
public:

    explicit Spawner(Ref<ZyEngine::Subsystem::Host> Host)
        : Locator { Host }
    {
    }

    void Refresh()
    {
        Ref<ZyScene::Service> Scene = GetService<ZyScene::Service>();
        // ...
    }
};

// In the kernel's OnInitialize, where every service exists:
mSpawner = Unique<Spawner>::Create(* this);
```

`Locator` resolves at construction, so construct it in `OnInitialize` or later, never in the kernel's constructor.

### 2.3 Writing a service

```cpp
class Herald final : public ZyEngine::Subsystem
{
public:

    explicit Herald(Ref<Host> Host)
        : Subsystem { Host }
    {
    }

    void OnTick(Real64 Delta) override
    {
        // Runs once per frame, with the other services.
    }

    void OnTeardown() override
    {
        // Runs once when the kernel tears every service down.
    }
};

// In a kernel's OnInitialize:
Register<Herald>();
```

Any code holding the host finds it the same way (`GetService<Herald>()`). Per-frame order against the engine's
services is not defined (section 1.4).

## 3. Engine modules and plugins

### 3.1 Engine modules

An engine module is a class deriving `ZyEngine::Module`, built as its own CMake target and registered with
`ZyRegisterModule`. The kernel creates one of each, calls `OnAttach(Host)` after the services exist and before the
graphic device opens, and `OnDetach(Host)` at shutdown while the services are still alive. The graphic drivers are
modules; this is their shape (from `Module/Graphic/Driver/D3D11/Source/D3D11Module.cpp`):

```cpp
Text Module::GetName() const
{
    return "D3D11";
}

void Module::OnAttach(Ref<ZyEngine::Subsystem::Host> Host)
{
    if (ConstRetainer<Service> Graphic = Host.GetService<Service>())
    {
        Graphic->Register(GetName(), Create, Service::Priority::High);
    }
}

void Module::OnDetach(Ref<ZyEngine::Subsystem::Host> Host)
{
    if (ConstRetainer<Service> Graphic = Host.GetService<Service>())
    {
        Graphic->Unregister(GetName());
    }
}
```

```cmake
ZyAddTarget(${PROJECT_NAME} STATIC)
TARGET_LINK_LIBRARIES(${PROJECT_NAME} PUBLIC "ZyEngine")
ZyRegisterModule(TARGET ${PROJECT_NAME} HEADER "D3D11Module.hpp" CLASS "ZyGraphic::D3D11::Module")
```

A module of your own (registering a service, a loader, a driver) follows the same three CMake lines. Register it
before the application's `ZyApplyModules` runs, since that call reads the list at configure time. Modules attach in
registration order.

### 3.2 Plugins: libraries loaded at run time

For code loaded from a shared library while the program runs, the engine has two CMake helpers and one class:

| Piece | Does |
|---|---|
| `ZyApplyExports(<host> [ALL] [MODULES <targets>...])` | Makes the host image (an executable or shared library) the one that carries the engine's marked symbols, and any listed modules, out to plugins. `ALL` carries every symbol, for plugins written against more than the marked parts. |
| `ZyApplyPlugin(<plugin> HOST <host>)` | Makes a `SHARED` or `MODULE` library a plugin of that host: it links the host for headers and the import side of `ZY_API`, and exports only what the plugin marks. |
| `ZY_EXPORT_C` | Marks an entry point in the plugin (`extern "C"` plus export). |
| `Library` (`Zyphryon.Base/System/Library.hpp`) | Loads a library (`Library(Text Path)`, `Open`, `Close`, `IsOpen`) and finds an entry point (`Ptr<void> GetSymbol(Text Name) const`). `Library::kExtension` is `dll`, `so` or `dylib`. |

```cpp
// In the plugin.
ZY_EXPORT_C void OnGreet()
{
    LOG_I("Greeter: hello from the plugin");
}

// In the host.
Library Greeter(Str::Print("Plugins/Greeter.{0}", Library::kExtension));

if (const Ptr<void> Symbol = Greeter.GetSymbol("OnGreet"))
{
    reinterpret_cast<void (*)()>(Symbol)();
}
```

The entry points and the contract between host and plugin are yours to design. Never replace a plugin's file on
disk while it is loaded; close the `Library` first.

## 4. Jobs: `Zyphryon.Job`

### 4.1 Lanes

```cpp
enum class ZyJob::Lane : UInt8
{
    Main,       // the main thread, drained once per frame in ZyJob::Service::OnTick
    Compute,    // one background worker per core but the main thread's
    IO,         // a small pool for work that blocks in the kernel, such as file access
};
```

At most `ZyJob::kMaxJobs` (1024) jobs are in flight. On a platform without threads (WebAssembly without
pthreads, `ZY_HAS_THREADS` undefined) every lane collapses to `Main`.

### 4.2 API

```cpp
class ZyJob::Service final : public ZyEngine::Subsystem
{
public:
    UInt32 GetConcurrency(Lane Target) const;          // worker threads behind a lane, 0 for Main

    void   Dispatch(Lane Target, AnyRef<Task> Work);    // fire and forget
    Handle Submit(Lane Target, AnyRef<Task> Work);      // then Wait(Handle) or Discard(Handle), exactly once
    void   Wait(Handle Job);                            // runs other compute jobs while it waits
    void   Discard(Handle Job);

    template<typename Callable>
    void Parallel(Lane Target, UInt32 Count, AnyRef<Callable> Callback, UInt32 Partition = 8);
};
```

`Task` is `Delegate<void()>`. `Parallel` splits `[0, Count)` into chunks and calls `Callback(Begin, End)` on the
caller and on workers, returning once every chunk is done. It asserts on `Lane::Main`.

### 4.3 Uses

Hop back to the main thread from a callback that may run elsewhere:

```cpp
GetService<ZyJob::Service>()->Dispatch(ZyJob::Lane::Main, [this, Level]
{
    // Safe to touch the scene here: this runs on the main thread, inside the job service's tick.
    Level.Add<Demo::Loaded>();
});
```

Split a heavy computation:

```cpp
Ref<ZyJob::Service> Jobs = * GetService<ZyJob::Service>();

Jobs.Parallel(ZyJob::Lane::Compute, static_cast<UInt32>(Cells.GetSize()), [&](UInt32 Begin, UInt32 End)
{
    for (UInt32 Index = Begin; Index < End; ++Index)
    {
        Cells[Index] = Score(Index);       // each index written by one worker only
    }
});
```

Run one task in the background and collect it later:

```cpp
const ZyJob::Handle Job = Jobs.Submit(ZyJob::Lane::Compute, [this]
{
    mPath = Search(mStart, mGoal);         // writes only state this task owns until Wait returns
});

// ... later, on the main thread:
Jobs.Wait(Job);
```

For walking entities in parallel, do not use `Parallel`. Declare the system `.Spread()` and the scene splits the
walk over the compute lane itself, measuring when it pays (see `scene.md`).

Rules:

- Never touch the scene from a job on `Compute` or `IO`. Only spread walks run scene callbacks off the main thread,
  and only inside the walk.
- Content reads take a lane for their callback: `Content.Read(Uri, ZyJob::Lane::Main, Callback)` hands the bytes
  back on the main thread (see `content.md`).
- A `Submit` handle must be waited or discarded once, or the job table fills.

## 5. Input: `Zyphryon.Input`

### 5.1 Polling

The platform service drains the window's events once per frame and hands them to the input service, which updates
every device. Polling reads that frame's state:

| Method | `true` when |
|---|---|
| `IsKeyPressed(Key)` | The key went down this frame. |
| `IsKeyHeld(Key)` | The key is down. |
| `IsKeyReleased(Key)` | The key went up this frame. |
| `GetModifiers()` | Returns `ZyInput::Modifier` bits: `Shift`, `Control`, `Alt`, `Super` (either side). |
| `GetMouseX()`, `GetMouseY()` | Cursor position in window pixels. |
| `GetMouseScrollX()`, `GetMouseScrollY()` | Wheel movement summed over the frame. |
| `IsMouseButtonPressed/Held/Released(Button)` | Same as keys. |
| `GetTouchPoints()`, `GetTouchCount()`, `FindTouch(ID)` | Touch points this frame. |

```cpp
if (ConstRetainer<ZyInput::Service> Input = GetService<ZyInput::Service>())
{
    if (Input->IsKeyPressed(ZyInput::Key::Escape))
    {
        Quit();
    }

    const Bool Walk = HasBit(Input->GetModifiers(), ZyInput::Modifier::Shift);
}
```

### 5.2 Key and button names

`ZyInput::Button`: `Unknown`, `Left`, `Middle`, `Right`, `Back`, `Forward`.

`ZyInput::Key` (the enum names are also the JSON names, matched case-insensitively):

| Group | Names |
|---|---|
| Letters | `A` ... `Z` |
| Number row | `Alpha0` ... `Alpha9` |
| Function | `F1` ... `F12` |
| Keypad | `Keypad0` ... `Keypad9`, `Decimal`, `Divide`, `Multiply`, `Subtract`, `Add` |
| Arrows and navigation | `Up`, `Down`, `Left`, `Right`, `PageUp`, `PageDown`, `Home`, `End`, `Insert`, `Delete` |
| Editing | `Space`, `Enter`, `Tab`, `Backspace`, `Escape` |
| Modifiers | `LeftShift`, `RightShift`, `LeftCtrl`, `RightCtrl`, `LeftAlt`, `RightAlt`, `LeftSuper`, `RightSuper`, `Menu` |
| Locks and system | `Capital` (Caps Lock), `Scroll`, `NumLock`, `Print`, `Pause` |
| Punctuation | `Apostrophe`, `Comma`, `Minus`, `Period`, `Slash`, `Semicolon`, `Equal`, `Backslash`, `Grave`, `LeftBracket`, `RightBracket` |
| Other | `Unknown` |

The number row is `Alpha1`, not `One` or `Key1`, and Caps Lock is `Capital`.

### 5.3 Events

The service exposes `MulticastDelegate` members. Handlers return `Bool`: `true` stops the event reaching handlers
added after it. Handlers run after every device has updated, so they read the frame's state.

| Member | Signature |
|---|---|
| `OnKeyDown`, `OnKeyUp`, `OnKeyRepeat` | `Bool(Key)` |
| `OnKeyType` | `Bool(Text)` (UTF-8 text typed) |
| `OnMouseDown`, `OnMouseUp` | `Bool(Button)` |
| `OnMouseMove` | `Bool(Real32 X, Real32 Y, Real32 DeltaX, Real32 DeltaY)` |
| `OnMouseScroll` | `Bool(Real32 DeltaX, Real32 DeltaY)` |
| `OnTouchDown`, `OnTouchMove`, `OnTouchUp` | `Bool(UInt32 ID, Real32 X, Real32 Y)` |
| `OnTouchCancel` | `Bool(UInt32 ID)` |
| `OnAction` | `Bool(UInt64 Action, ZyInput::Action State)` (after the frame's other events) |
| `OnWindowFocus`, `OnWindowResize`, `OnWindowScale`, `OnWindowExit` | `Bool(Bool)`, `Bool(UInt32, UInt32)`, `Bool(Real32)`, `Bool()` |

```cpp
Bool OnInitialize() override
{
    GetService<ZyInput::Service>()->OnKeyDown.AddMethod<&Application::OnKeyDown>(this);
    return true;
}

void OnTerminate() override
{
    GetService<ZyInput::Service>()->OnKeyDown.RemoveMethod<&Application::OnKeyDown>(this);
}

Bool OnKeyDown(ZyInput::Key Key)
{
    if (Key == ZyInput::Key::F11)
    {
        Ref<ZyPlatform::Window> Window = GetService<ZyPlatform::Service>()->GetWindow();
        Window.SetFullscreen(!Window.IsFullscreen());
        return true;                    // later handlers never see F11
    }
    return false;
}
```

`AddLambda` exists too, but a lambda cannot be removed by identity; prefer `AddMethod` for anything that must be
taken back.

Consuming is what lets an interface layer take keys before the game: register the interface's handler first, have
it return `true` for keys it uses (typing into a text field), and the game's handlers added later never hear them.
Polling has no such filter, since `IsKeyPressed` reads device state whatever a handler did with the event. Use
events for keys that must not fire while the player types.

The kernel itself listens to `OnWindowExit` (calls `Quit()`), `OnWindowResize` (resets the swapchain) and
`OnWindowFocus` (suspends and restores audio when `Startup::Audio::Pause` is set). It returns `false` from each, so
your handlers still hear them.

When the window loses focus the service releases every held key and button and sends the matching up events, so
a held movement key never sticks.

### 5.4 Actions: `Mapping`

Actions are named inputs a program reads instead of raw keys, so bindings can change without code.

```cpp
Ref<ZyInput::Mapping> Mapping = Input->GetMapping();

Mapping.Bind("Attack",  ZyInput::Binding::FromButton(ZyInput::Button::Left));
Mapping.Bind("Attack",  ZyInput::Binding::FromKey(ZyInput::Key::LeftCtrl));
Mapping.Bind("Forward", ZyInput::Binding::FromKeys(ZyInput::Key::S, ZyInput::Key::W));   // -1 .. +1
Mapping.Bind("Turn",    ZyInput::Binding::FromAxis(ZyInput::Axis::MoveX, 0.2f));

static constexpr UInt64 kAttack = ZyInput::Mapping::Identify("Attack");   // a compile-time hash

if (Input->IsActionPressed(kAttack))
{
    // swing
}
const Real32 Forward = Input->GetActionValue(ZyInput::Mapping::Identify("Forward"));
```

| Binding factory | Reads |
|---|---|
| `Binding::FromKey(Key, Scale = 1)` | `Scale` while the key is held. |
| `Binding::FromButton(Button, Scale = 1)` | `Scale` while the button is held. |
| `Binding::FromKeys(Negative, Positive, Scale = 1)` | `-Scale` / `+Scale`. |
| `Binding::FromAxis(Axis, Scale = 1)` | Mouse movement or scroll this frame times `Scale`. `Axis`: `MoveX`, `MoveY`, `ScrollX`, `ScrollY`. |

Queries: `IsActionPressed`, `IsActionHeld`, `IsActionReleased`, `GetActionValue`, all taking the `UInt64` from
`Mapping::Identify`. An action's value is its keys and buttons summed and clamped to `[-1, 1]`, plus its mouse axes
and anything fed with `Mapping.Feed(Name, Value)` (a gamepad or an on-screen stick). It is held while the value is
not zero.

`Mapping.Save(Root)` and `Mapping.Load(Root)` write and read bindings, one array per action:

```json
{
  "Attack":  [ { "Button": "Left" }, { "Key": "LeftCtrl" } ],
  "Forward": [ { "Negative": "S", "Positive": "W" } ],
  "Turn":    [ { "Axis": "MoveX", "Scale": 0.2 } ]
}
```

`Load` replaces only the bindings of actions already defined in code, so bind defaults first, then load the
player's file over them. A misspelled name is skipped with a warning.

## 6. The window

`ZyPlatform::Service::GetWindow()` returns the one `ZyPlatform::Window`; `GetDisplay()` returns the monitors.

| Method | Use |
|---|---|
| `SetTitle(Text)`, `GetTitle()` | Title bar text. |
| `SetPosition(SInt32 X, SInt32 Y)`, `GetX()`, `GetY()` | Position on the desktop. |
| `SetSize(UInt32 Width, UInt32 Height)`, `GetWidth()`, `GetHeight()` | Size in pixels. |
| `GetScale()` | The monitor's scale (1 at standard density). Startup sizes are before the scale. |
| `SetFullscreen(Bool)`, `IsFullscreen()`, `IsWindowed()`, `IsBorderless()` | Mode. |
| `SetVisible(Bool)`, `IsVisible()`, `SetFocus()`, `IsFocused()` | Visibility and focus. |
| `SetCursorPosition(UInt32 X, UInt32 Y)`, `SetCursorLock(Bool)`, `IsCursorLocked()` | Cursor. |
| `SetClipboard(Text)`, `GetClipboard() -> Str` | System clipboard. |
| `GetHandle()` | Native handle for the graphic driver. |

```cpp
Ref<ZyPlatform::Window> Window = GetService<ZyPlatform::Service>()->GetWindow();
Window.SetTitle(Str::Print("Hello ({0:.0} fps)", GetMeter().GetRate()));
```

Draw at the window's current `GetWidth()` and `GetHeight()` every frame; the kernel resizes the swapchain on its
own when the window changes size.

## 7. Audio

`ZyAudio::Service` plays baked `.snd` sounds through a 48 kHz stereo mixer, with five category submixes (`Music`,
`Effect`, `Voice`, `Ambient`, `Interface`), at most 256 playbacks at once, and spatial voices through an emitter and
a listener. Backends: WASAPI on Windows, ALSA on Linux, WebAudio on the web. `audio.md` covers the service in full.
The smallest use:

```cpp
#include <Zyphryon.Audio/Service.hpp>

ConstRetainer<ZyAudio::Service> Audio = GetService<ZyAudio::Service>();
mRain = GetService<ZyContent::Service>()->Load<ZyAudio::Sound>("Resources://Sound/Rain.snd");

// Once the sound has loaded (see content.md for Await):
const ZyAudio::Object Loop = Audio->Play(ZyAudio::Category::Ambient, mRain, 0.6f);
Audio->SetPlaybackLooping(Loop, true);
```

`Play` returns `0` when it fails. A machine with no output device starts with the warning
`Kernel: Failed to initialize audio service, continuing without sound` and stays silent.

## 8. Behaviour trees

`Zyphryon.AI` (namespace `ZyAI`) is a generic behaviour-tree runtime with no knowledge of the scene: a `.bhv` tree
resource (`ZyAI::Behaviour`), a per-agent `ZyAI::Brain` with its `ZyAI::Blackboard`, and a `ZyAI::Host` interface
your code implements to run the leaves. `ai.md` covers it in full. The one runtime fact to know here: no engine
service registers the `.bhv` loader, so a program that uses trees adds it in `OnInitialize`:

```cpp
#include <Zyphryon.AI/Loader/BHVLoader.hpp>

Ref<ZyContent::Service> Content = * GetService<ZyContent::Service>();
Content.AddLoader(ZyAI::BHVLoader::kTypes, Retainer<ZyAI::BHVLoader>::Create());
```

## 9. Profiling

The profiling macros come from `Zyphryon.Base/Telemetry/Profiler.hpp`. They compile to nothing unless the build
defines `ZY_PROFILE_BACKEND_TRACY` (the CMake option of the same name; the `profile` preset turns it on).

| Macro | Use |
|---|---|
| `ZY_PROFILE` | A zone named after the function, with a callstack. |
| `ZY_PROFILE_SCOPE("Name")` | A named zone for the rest of the scope. |
| `ZY_PROFILE_NAMED(Data, Size)` | A zone named at run time (cheap in loops). |
| `ZY_PROFILE_INTEGER("Name", Value)`, `ZY_PROFILE_REAL("Name", Value)` | Plot a value. |
| `ZY_PROFILE_FRAME` | Frame mark (the kernel emits it each tick). |
| `ZY_PROFILE_THREAD("Name")` | Names the current thread (the kernel names the main thread). |

```cpp
void Demo::Pack::Hunt()
{
    ZY_PROFILE_SCOPE("Demo::Pack::Hunt");
    // ...
}
```

Every scene system is already a zone named after its system name, so naming systems well is most of what profiling
a game needs. Each engine service's tick is a zone too (`Platform::Tick`, `Scene::Tick`, `Graphic::Tick` ...).

Tracy is built with `TRACY_ON_DEMAND`: nothing is collected until a Tracy viewer (v0.13.1, the version the build
fetches) connects to the running program, and collection then fills memory for as long as it stays connected.
`ZY_PROFILE_MEMORY` (off by default) also reports every allocation.

Without Tracy, `Kernel::GetMeter().GetRate()` gives the measured frames per second over the last half second.

## 10. Platform notes

| Topic | Notes |
|---|---|
| Platforms | Windows and Linux desktop, WebAssembly (Emscripten). macOS is detected by the headers; Android errors at compile time. |
| Graphic drivers | `D3D11` (Windows only, preferred) and `OpenGL` (desktop GL and WebGL 2). Pick by `Startup::Graphic::Driver` or the settings `"driver"` key. |
| Colour target | Picked from the monitor when unspecified (`RGBA16Float` on HDR monitors, `RGBA8UIntNorm_sRGB` otherwise). Set `ColorFormat` yourself for a fixed target. |
| Audio | WASAPI (Windows), ALSA (Linux), WebAudio (web). |
| Threads | Present unless built for the web without pthreads (`ZY_WEB_THREAD`, off by default). Without threads every job lane runs on the main thread and spread walks run inline. |
| Web loop | The browser drives frames; `Startup::SetRate` is ignored there. |
| Headless | `ZY_MODE_HEADLESS` build, or `Startup::SetHeadless(true)` at run time (section 1.7). |
| Tick rate | `Startup::SetRate(N)` caps the loop at N ticks per second, 0 means uncapped. A tick that ran long is made up on the next one. |
| Network | The network service may fail to start; it is then not registered. Check `GetService<ZyNetwork::Service>()`. |

## 11. Worked example: a kernel with a service, actions and a background job

A small program that binds two actions, keeps a score in a service of its own, and computes a heavy table on the
compute lane at start-up without blocking the first frames.

```cpp
#include <Zyphryon.Graphic/Service.hpp>
#include <Zyphryon.Input/Service.hpp>
#include <Zyphryon.Job/Service.hpp>
#include <Zyphryon.Platform/Service.hpp>
#include <Zyphryon.Runtime/Entry.hpp>

namespace Demo
{
    // A service of the program's own: found by anyone holding the host.
    class Score final : public ZyEngine::Subsystem
    {
    public:

        explicit Score(Ref<Host> Host)
            : Subsystem { Host },
              mPoints   { 0 }
        {
        }

        void OnTick(Real64 Delta) override
        {
            ZY_PROFILE_INTEGER("Score", mPoints);
        }

        void Add(UInt32 Points)
        {
            mPoints += Points;
        }

        UInt32 GetPoints() const
        {
            return mPoints;
        }

    private:

        UInt32 mPoints;
    };

    class Application final : public ZyRuntime::Kernel
    {
    public:

        Application()
            : mJob   { },
              mReady { false }
        {
        }

    protected:

        void OnConfigure(Ref<ZyRuntime::Startup> Startup) override
        {
            ZyRuntime::Startup::Window Window = Startup.GetWindow();
            Window.Title = "Score";
            Startup.SetWindow(Window);
        }

        Bool OnInitialize() override
        {
            Register<Score>();

            Ref<ZyInput::Mapping> Mapping = GetService<ZyInput::Service>()->GetMapping();
            Mapping.Bind("Score", ZyInput::Binding::FromKey(ZyInput::Key::Space));
            Mapping.Bind("Score", ZyInput::Binding::FromButton(ZyInput::Button::Left));
            Mapping.Bind("Quit",  ZyInput::Binding::FromKey(ZyInput::Key::Escape));

            // The table fills on a worker; only this task writes it until Wait returns.
            mTable.Advance(1 << 16);
            mJob = GetService<ZyJob::Service>()->Submit(ZyJob::Lane::Compute, [this]
            {
                for (UInt Index = 0; Index < mTable.GetSize(); ++Index)
                {
                    mTable[Index] = Sqrt(static_cast<Real32>(Index));
                }
            });
            return true;
        }

        void OnTick(Real64 Delta) override
        {
            ConstRetainer<ZyInput::Service> Input = GetService<ZyInput::Service>();

            if (Input->IsActionPressed(ZyInput::Mapping::Identify("Quit")))
            {
                Quit();
            }

            if (Input->IsActionPressed(ZyInput::Mapping::Identify("Score")))
            {
                GetService<Score>()->Add(1);
                LOG_I("Demo: {0} points", GetService<Score>()->GetPoints());
            }

            if (!mReady)
            {
                GetService<ZyJob::Service>()->Wait(mJob);      // the job had the first frames to finish
                mReady = true;
                LOG_I("Demo: table ready, last entry {0:.2}", mTable.GetBack());
            }

            ConstRef<ZyPlatform::Window> Window = GetService<ZyPlatform::Service>()->GetWindow();

            ConstRetainer<ZyGraphic::Service> Graphic = GetService<ZyGraphic::Service>();
            Graphic->Prepare(ZyGraphic::kDisplay, "Clear",
                ZyGraphic::Viewport(0.0f, 0.0f, static_cast<Real32>(Window.GetWidth()), static_cast<Real32>(Window.GetHeight())),
                Color(0.05f, 0.05f, 0.08f, 1.0f), 1.0f, 0);
            Graphic->Commit();
        }

        void OnTerminate() override
        {
            if (!mReady)
            {
                GetService<ZyJob::Service>()->Wait(mJob);      // a submitted job is waited once, even on the way out
            }
        }

    private:

        Sequence<Real32> mTable;
        ZyJob::Handle    mJob;
        Bool             mReady;
    };
}

ZY_APPLICATION(Demo::Application)
```

`Identify` is `constexpr`, so the hashes above cost nothing at run time; hoisting them into `static constexpr`
members reads better in a real program.

## 12. Common mistakes

| Mistake | What happens | Do instead |
|---|---|---|
| Reaching for a service in `OnConfigure` or the kernel's constructor | Empty retainer; a `Locator` asserts. | `OnInitialize` or later. |
| Touching the scene from a `Compute` or `IO` job | Data races, crashes. | `Dispatch(ZyJob::Lane::Main, ...)` back, or a spread system. |
| Using `ZyJob::Service::Parallel` to walk entities | Bypasses deferral and change tracking. | `.Spread()` on the system. |
| Polling keys for actions that must not fire while typing | Fires anyway. | `OnKeyDown` handlers, behind an interface handler that consumes them. |
| Adding input handlers without removing them | A handler is called after its object is gone. | `AddMethod` in `OnInitialize`, `RemoveMethod` in `OnTerminate`. |
| Assuming input, graphics or audio exist | Empty retainer in a headless run. | Check `GetService<T>()`. |
| A headless loop without `SetRate` | One core spins at 100 %. | `Startup.SetRate(N)`. |
| `Key::One` / `Key::Num1` | No such names. | `Key::Alpha1`. |
| Loading `.bhv` without adding the loader | `Content: Unknown file format 'bhv'`, the resource fails. | `AddLoader(ZyAI::BHVLoader::kTypes, ...)`. |
| A `Submit` handle never waited or discarded | The 1024-job table fills. | `Wait` or `Discard` it once. |
| Expecting profiling in a build without `ZY_PROFILE_BACKEND_TRACY` | Macros are empty. | Build with the option, connect Tracy. |
| Holding the `Text` from `GetOperands()` or `GetText` past the kernel | It borrows the parsed command line. | Copy it into a `Str`. |
